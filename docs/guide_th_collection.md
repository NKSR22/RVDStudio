# คู่มือเก็บข้อมูล (ภาษาไทย)

เอกสารนี้อธิบายว่าโปรแกรม GUI ของเราเก็บข้อมูล “ยังไง” และควรเก็บแบบไหนให้เอาไปเทรนต่อได้ผลดี

## ระบบปฏิบัติการที่รองรับ

โปรเจกต์นี้ออกแบบให้ใช้ได้กับ:

- `Windows`
- `macOS`
- `Ubuntu`

ตัวแอพ GUI ใช้ `PySide6 + OpenCV` ซึ่งรองรับหลายระบบ แต่หมายเลขกล้อง (`0`, `1`, `2`) อาจไม่เหมือนกันในแต่ละเครื่อง

## โปรแกรมเก็บอะไรบ้าง

เมื่อคุณกด `Capture Frame` โปรแกรมจะบันทึก 2 อย่างลง `data/raw/`:

1. รูปภาพ `.jpg` (เฟรมจากเว็บแคม)
2. ไฟล์ metadata `.json` (ข้อมูลประกอบของเฟรม)

โครงสร้างโฟลเดอร์ตัวอย่าง:

```text
data/raw/
  <session_name>/
    images/
      20260403_214022_466269.jpg
    meta/
      20260403_214022_466269.json
```

สิ่งที่อยู่ใน metadata (ตัวอย่างแนวคิด):

- เวลา (timestamp)
- ชื่อกล้อง (เช่น `robot_webcam_front`)
- ชื่อ session (เช่น `warehouse_morning_001`)
- scene tag ที่คุณเลือก (`stop_wait`, `bypass_left`, `bypass_right`, `blocked`, `clear`)
- note ที่ผู้ใช้พิมพ์
- model ที่ใช้ตอนเก็บ (เช่น `yolo11n.pt`)
- ค่า confidence threshold
- ขนาดภาพ (กว้าง/สูง)
- รายการ detections (label, confidence, bbox)

## แนวทางการเก็บข้อมูลให้เหมาะกับหุ่นยนต์จริง

- ใช้เว็บแคมตัวจริง ติดตำแหน่งจริง มุมจริง
- เก็บในพื้นที่จริงและแสงจริง (สว่าง/ปกติ/มืด/ย้อนแสง)
- เก็บทั้งเคสง่ายและเคสยาก
- เน้นเก็บ “เคสที่โมเดลพลาด” เพราะมีค่าต่อการเทรนมากที่สุด
- อย่าเก็บแต่ภาพที่มีสิ่งกีดขวาง ควรมี `clear` (ไม่มีวัตถุ) ด้วย

## กติกาเบื้องต้นของงานนี้

- ถ้าเจอ `person` ในทางเดิน ให้ tag เป็น `stop_wait` เป็นค่าเริ่มต้น
- ถ้าเป็นวัตถุ (สิ่งกีดขวาง) ให้ tag เป็น `bypass_left` หรือ `bypass_right` ตามที่เห็นว่าปลอดภัยกว่า
- ถ้าซ้าย/ขวาไม่ปลอดภัย ให้ `blocked`

หมายเหตุ: การตัดสินใจจริงเรื่องซ้าย/ขวาในหุ่นยนต์ควรใช้ LiDAR ร่วมด้วย แต่ tag นี้ช่วยให้เราจัดหมวดหมู่ฉากเพื่อเรียนรู้/วิเคราะห์ภายหลัง

## วิธีเปิดโปรแกรมตามระบบ

`macOS / Ubuntu`

```bash
source .venv/bin/activate
python -m app.gui
```

`Windows PowerShell`

```bash
.venv\Scripts\Activate.ps1
python -m app.gui
```
